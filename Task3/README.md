# Task 3. Data Encryption at Rest and In Transit

В рамках данного задания проведена классификация данных компании, обоснована необходимость защиты и подобраны инструменты для защиты данных как при хранении (at rest), так и при передаче (in transit).

---

## Классификация и защита данных

| Данные | В чём необходимость защиты | Инструменты защиты |
|--------|-----------------------------|--------------------|
| Персональные данные (PII) : ФИО, дата рождения, телефон, e-mail, адрес | Высокий риск утечки и нарушение законодательства РФ и GDPR. Необходимо ограничить доступ, исключить утечку и обеспечить контроль согласия на обработку. | Шифрование на диске (AES-256), RBAC/ABAC через IAM, токенизация, DataGrail для тегирования, TLS 1.3 при передаче |
| Медицинские данные (PHI) : диагнозы, анализы, заключения | Критически чувствительные данные. Утечка влечёт не только штрафы, но и репутационные потери. | Шифрование на уровне поля (Postgres pgcrypto, Always Encrypted), TLS 1.3 при передаче, токенизация PHI, ABAC по ролям, DLP для e-mail |
| Финансовые данные : платежи пациентов, суммы, реквизиты, чеки ККМ | Конфиденциальные данные, обязательны по закону о ККТ и для защиты от мошенничества. | Шифрование базы (TDE), TLS для интеграции ККМ и банка, RBAC в 1С и PaymentsService, журналирование транзакций, DLP для карт- и платежных данных |
| Документы : сканы паспортов, договоры, PDF, JPG | Содержат PII и иногда финансовые данные. Часто расшариваются без защиты. | Шифрование файлового хранилища (BitLocker, eCryptfs), Azure Information Protection/IRM для меток, тегирование «personal_data» |
| Данные склада : накладные, заявки, инвентаризация | Чувствительность средняя, но могут содержать PII (в заявках). Нужно разграничить доступ и предотвратить утечки. | RBAC по ролям (warehouse/bookkeeper), TLS при обмене с 1С, DataGrail для тегов, аудит изменений |
| Логи и аудит | Могут содержать PII (идентификаторы), необходимы для расследований. Утечка подрывает безопасность. | WORM-хранилище, шифрование логов, контроль доступа, корреляция событий, Immutable Audit (Kafka + Object Storage) |
| Данные аналитики (Data Lakehouse) | Используются для BI и ML. Нельзя хранить PII без де-идентификации. | Де-идентификация и анонимизация при загрузке, TLS для потоков ingest, теги lineage, ограничение доступа на уровне строк и представлений |

## Автоматизированный контроль

- **DataGrail / Informatica Data Catalog** : автоматическое тегирование и классификация данных.  
- **Collibra Data Intelligence** : проверка корректности тегов, выявление данных без меток.  
- **DLP (Symantec, McAfee)** : сканирование исходящей почты и файлов на PII/PHI/финансовые шаблоны.  
- **Audit and Logging (Kafka + Object Storage, WORM)** : централизованный неизменяемый журнал.  
- **Service Mesh (Istio/Linkerd)** : mTLS по умолчанию, политика безопасности сервис-сервис.

## Реестр программных и аппаратных средств защиты

| Средство | Класс | Назначение |
|----------|-------|------------|
| Keycloak / Azure AD | IAM | Управление идентификацией, RBAC/ABAC, MFA |
| OPA (Open Policy Agent) | PDP | Централизованное принятие решений по политикам доступа |
| Vault / KMS | HSM / Secrets Management | Управление ключами шифрования и секретами |
| DataGrail | Data Discovery & Tagging | Автоматическая классификация и тегирование данных |
| Symantec DLP or McAfee DLP | Data Loss Prevention | Мониторинг и предотвращение утечек |
| Collibra | Data Governance | Контроль корректности тегов и метаданных |
| Veeam Backup, Snapshotting | Backup & DR | Резервное копирование и восстановление |
| Istio / Linkerd | Service Mesh | mTLS, управление сетевыми политиками |
| Azure Information Protection / IRM | Information Rights Mgmt | Метки и защита файлов и документов |
| Postgres (pgcrypto), SQL Server Always Encrypted | Database Encryption | Шифрование на уровне полей и таблиц |

## Итог
Система требует защиты всех ключевых классов данных (PII, PHI, финансовые, документы, ТМЦ, логи, аналитика). Применены меры защиты на уровне хранения (AES, TDE, WORM, field-level encryption), передачи (TLS 1.3, mTLS в mesh), а также организационные механизмы (IAM, RBAC/ABAC, токенизация, тегирование, DLP). Автоматизированный контроль обеспечивается средствами Data Discovery, DLP и централизованным аудитом.
